## Commits

Use the Conventional Commits format for all commit messages, for example `feat: add workspace setup` or `fix(web): handle empty state`.

## Branches

Name branches `type/short-description`, using the same types as commit messages, for example `feat/social-card` or `fix/editor-empty-state`.

## UI text

Don't use all-caps text, whether typed in caps or styled with `uppercase` / `text-transform`. Use it only where caps carry meaning, such as acronyms (HDR, FPS) or initials.

Never use the middle dot (`·`) in UI text, including as a separator between pieces of metadata. Separate them with spacing (a flex `gap`) instead.
